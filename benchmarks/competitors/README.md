# Reproducible competitor benchmark

This directory turns the August 2026 diagnostic comparison into inspectable,
recomputable evidence. It contains the exact normalized outputs and parsed ASTs
used for scoring, execution records, pinned tool versions, fixture hashes, and a
standard-library-only scorer.

The benchmark is deliberately separate from package runtime code. Competitor
packages are not dependencies, are not redistributed, and retain their own
licenses. The committed text outputs are benchmark observations, not copies of
competitor source code.

## Recompute the report

From the repository root:

```bash
python3 benchmarks/competitors/score.py --check
```

That command recomputes `results.json` and `REPORT.md` in memory and fails if
either committed artifact has drifted. To refresh them after adding a run:

```bash
python3 benchmarks/competitors/score.py --write
```

The scorer uses only Python's standard library. Character and word scores are
`difflib.SequenceMatcher` ratios after Unicode NFC normalization and whitespace
collapse. Structural recall is the fraction of distinct non-generic Carve AST
node kinds in the ground truth that also occur in the normalized candidate AST.
This metric rewards representational breadth, not the number or correctness of
individual nodes; the report therefore publishes its numerator and denominator.
`results.json` also binds every raw observation to its SHA-256 digest, so changes
that happen not to affect a score are still detected.

## Corpus

The inputs are generated by the `carve-pdf` project from their corresponding
Carve ground truths. They are fetched from the pinned fixture commit rather than
vendored here. `fixtures.json` records immutable URLs and SHA-256 hashes.

```bash
python3 benchmarks/competitors/fetch_fixtures.py /tmp/carve-pdf-benchmark
```

The two fixtures cover inline decoration and editorial markup, a spanning
table, figure/caption, admonition, quotation, footnote, equations, Mermaid
diagrams, and a Chart.js chart. This is a small stress corpus, not a universal
leaderboard.

## Rerunning extractors

`runs.json` records the exact package version, command shape, completion status,
runtime, and peak RSS for each run. Commands use `{input}` and `{output}`
placeholders so paths do not affect provenance. Heavy tools should be installed
in isolated environments at the recorded versions.

[`TOOLS.md`](TOOLS.md) links every project, records measured-version licensing,
and explains eligibility decisions such as why Pandoc is not treated as a PDF
extractor.

After an extractor produces Markdown, normalize it through the official Carve
Markdown importer and plain-text renderer, then place both the resulting AST
and plain text under `raw/<tool>/`. Plain-text-only extractors may omit the AST;
their structural score is reported as unavailable rather than guessed.

The vision-backed competitors require provider credentials. One tool could not
produce a fidelity sample because the available OpenAI account returned a
credit-exhaustion response. Its zero-byte output, sanitized stderr, successful
process exit, and timing are retained because this is a meaningful fail-open
automation result, but it is excluded from quality averages.

## Interpretation rules

- Missing and timed-out documents are never silently averaged as zero-quality
  successes. Completion is reported separately and quality averages use only
  completed, non-empty outputs.
- AI output is nondeterministic. The committed vision run is one sample.
- Claude CLI cost fields are API-equivalent telemetry reported by the CLI, not
  a claim that subscription-authenticated runs incurred an additional charge.
- Runtime and RSS were measured sequentially on the machine described in
  `runs.json`; they are operational observations, not cross-platform promises.
- The Markdown normalization step is shared by all Markdown-producing tools.
- Results should be regenerated when fixtures, normalization, scorer, model,
  prompts, or tool versions change.
